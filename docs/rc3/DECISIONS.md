# RC3 decisions

1. **Pre-RC3 tree committed** as `1792043` (owner approved) so RC3 commits stay isolated.
2. **Internal identifiers keep `qanouni`/`Rafiq` names** (locales/qanouni, MascotRafiq.jsx, `qanouni_lang`, DB/IDB names, branch, APK file names): renaming breaks installed apps and user data; they are not brand strings.
3. **Migration naming** follows the repo timestamp convention: `<ts>_rc3_pN_<topic>`.
4. **`gate-base` tag untouched.**
5. **Locale placeholders use `{0}`** (repo's `tr()` convention), not `{{brand}}`. Arabic text is the key, so brand-bearing keys were rewritten with `{0}` and the `رفيق` keys removed from ary/fr/en.
6. **Legal notice** keeps version 1.1.0: only the product name changed (now interpolated from BRAND), not the substance.
7. **Render tests** use `server/utils/law/testing/renderJsx.js` (esbuild + react-dom/server) since the repo has no jsdom/RTL; jest config untouched.
8. `index.html` / `manifest.json` literals updated directly (brand-string gate only scans js/jsx).
9. **Mobile bar** shows today, path, exam, timetable, community + "More" (library, profile, settings), as specified.
10. **jsdom** added as a root devDependency to test popover/QR interactions (no runtime impact). The render helper lives in `server/utils/law/testing/` because jest treats anything under `__tests__` as a test.
11. **`/law/review` is now `/law/exam/cards`** (FSRS page unchanged); `/law/review` and `/law/review/weak-spots` redirect.
12. Friend QR encodes the existing `/law/profile?add=<code>` link; the scanner also accepts desktop sign-in QRs and typed codes. Code format becomes `XXXX-XXXX` in Phase 7.
13. **Modules (Phase 3) reuse `LawCourseModule`**, not a new `LawModule`: a student's own module is the same row with `ownerId` set (parcours `u<id>`, `source` seed|custom, `verified`), so the path graph, progress and hub pins work unchanged. Per-student tables (`LawModuleProfile`, `LawProfessorCard`, `LawLectureSource`, `LawModuleNode`, `LawModuleProposal`) are keyed by `(userId, moduleId)` with string ids; the prompt's `Int moduleId @unique` assumed a per-user module table that does not exist. Migration `20261102090000_rc3_p3_modules` rebuilds `LawCourseModule` (Prisma RedefineTables) to add the three columns; children and progress verified intact on a copy.
14. **Existing test `phase9 › modules` asserts an empty list for S3 private/AR before any timetable is published**, which contradicts spec 3.1 (seeded defaults for exactly that scope). Tests may not be edited, so `GET /law/path/semesters/:s/modules` keeps its contract (official modules only) and the seeded list is served by the new `GET /law/modules?semester=`; the Path hub uses the new endpoint.
15. **Ingestion reuses the capture pipeline**: media is queued on the device (`queueImport`/`queuePhotoBatch`, images resized client-side), the module source names the device batch (`clientBatchId`) and moves pending → processing → ready by watching the batch's OCR/transcript derivatives. Raw audio is deleted after transcription unless `keepRaw`; audio requires an explicit recording-permission acknowledgement (one-time notice on the client, required flag on the server).
16. **Mentor** is a new AI purpose `module_mentor` through the existing router. Answers must cite retrieved source labels or are replaced; statute numbers it brings from memory are stripped and reported (`scrub`); build mode only creates pending proposals (diffs), applied on accept, stale-checked against the node body.
17. **Exam Center drills are generated from the student's own module material** (notes + ready lecture sources), not from the statute corpus. Every item must cite a labelled source piece or it is dropped; if nothing grounded survives the AI turn is refunded and nothing is stored. The answer key, references and the exact source text live in `promptJson` and are returned only after the attempt is submitted (QCM is graded locally with no AI call; case/direct/dissertation get one critique call whose verdicts, not a model-made number, produce the score). A critique outage keeps the attempt open with the student's text saved.
18. **`LawExamDate.moduleId` is a `String`** (LawCourseModule ids are cuids) and `LawDrillAttempt` gets `status` + `updatedAt` beyond the prompt's schema (user data needs `updatedAt`; the API needs open vs submitted). Imported dates are stored with `confirmed = false` and are invisible to the countdown, Today and the radar until the student confirms (optionally with corrections). Wall-clock times are converted with `zonedInstant` (Africa/Casablanca zone rules, no fixed offset).
19. **Readiness radar axes**: cards (mastered share of the linked subject's flashcards), path (completed stages), drills (mean of the last five scores), notes (share of notes with text), gaps (share of closed gaps in the linked course notes). A missing axis is `null` ("no data"), never zero; the overall is the mean of what exists.
20. **`LawTimetableSession` is realised as the existing `LawTimetableSlot`** (the student's weekly sessions), extended additively with `professor`, `groupLabel`, `moduleId` and the `TP` kind; a second table would have duplicated the data and broken class auto-labelling in the capture pipeline. `LawReminderPref` is new (plus `lastEveningFor`, `createdAt`, `updatedAt`).
21. **Importers** (`server/utils/law/timetable/importers/{manual,ics,csv,image,fdcAdapter}.js`) all produce the same validated *candidate* shape and never save: the client review step (shared by photo, text, ICS and CSV) corrects them and saves through the existing `PUT /law/timetable`. ICS times are converted with the Casablanca zone rules (UTC, other TZIDs, floating); unsupported recurrences keep the first occurrence and warn; bad rows are reported by line. `fdcAdapter` is an interface only (`NOT_IMPLEMENTED`; no scraping, no credentials); the official timetable keeps arriving through the reviewed FDC publication pipeline.
22. **Reminders** run beside `scheduler.due()` (not inside it: `due()` is pinned by existing tests). The evening-before reminder is **in-app only** (notification + Today card) because the existing acceptance test "Sunday recap arrives as push" pins exactly one push at Sunday 20:30 and an evening push would be a second one; the minutes-before reminder, which the student opts into, does push. Each reminder is claimed atomically (`lastEveningFor` conditional update; per-session key for the N-minutes reminder), so repeated ticks never duplicate.
23. **The corpus catalog is names only.** `server/data/law/corpus/catalog.json` lists three categories (basic codes, organic and framework laws, dahirs and decrees) with every entry `pending_source`: no article text, article numbers or official URLs are written from memory. An entry becomes available only after a file is ingested with `server/scripts/law/ingest-corpus.js`.
24. **Ingestion stages for review.** `corpusIngest.ingestFile` requires a plain `.txt`/`.md` file, an `https` source URL and a strict `--as-of` consolidation date (`LawSourceDocument.consolidatedAsOf`), records the sha256, is idempotent per sha256+code, and by default stages a review import; `--commit` writes directly. Nothing ingests silently.
25. **Library relocation.** The Library hub shows the three corpus categories; the AI chat stays as a compact link and the legal notice as a footer link. Courses moved to the study path (`/law/path/courses[/:id]`, legacy `library/courses` redirects kept); the capture entry lives on Today.
26. **Phase 6 critic fixes.** `--commit` on an already staged file publishes that import (it used to report "unchanged"); committed ingested text leaves its code flagged `reviewed:false` until a person reviews it; the catalog endpoint selects only provenance columns. The judicial-organisation entry is named neutrally ("التنظيم القضائي للمملكة", numbering label "المادة"): the exact instrument and its numbering label are confirmed when the official source is ingested, not guessed in the catalog.
27. **Friend codes.** New students get a second, shareable code `XXXX-XXXX` (`LawUserProfile.shareCode`, 29-character unambiguous alphabet, unique) beside the legacy `QAN-NAME-1234`, which stays valid because existing tests and shared links pin it. Both are accepted by `POST /law/friends` and `GET /law/social/find`; a bare 8-letter search term is still a handle search (the share code needs its dash there). The WhatsApp link is built server side (`GET /law/friends/code`).
28. **Squad roles extend, not replace, Collab squads.** `LawSquadMember.role` gains `admin|editor|viewer` (the stored legacy `contributor` is read as `editor`), one table in `utils/law/permissions.js` serves every endpoint. Owner assigns anything below owner and transfers ownership; an admin only manages editors/viewers; an admin cannot approve their own change request (the owner can). The older master notes / Faculty Hub change requests are untouched; the new `LawSquadDoc*` models (work-only types `summary|case_brief|mock_exam|question|resource_link`) reuse the same block-level three-way merge (`hubMerge`) with stale-base detection both on direct edits (`baseRevisionId` required, 409 `stale_base`) and on merge (CONFLICT until the author rebases). Joining by invite code still gives `contributor` (an editor).
29. **Campus wall** is scoped to `LawUserProfile.facultyCode`: announcements are admin-only, students open `td_thread`s and reply, no images/reactions, at most two links per post, rate limited. Three distinct reporters hide a post automatically; an admin upholds (stays hidden) or dismisses (restores). Blocked students never see each other. New back-relations on `users` are documented in UPSTREAM_TOUCHPOINTS.
30. **Avatar studio** stays inside `components/LawOS/avatar/` and extends the existing closed vocabulary additively (old stored configs still validate): `face`, `expression`, outfits `judge|lawyer|adoul|professor|student`, headwear `rezza`, accessories `scales|scroll`. Moroccan attire is colour and shape only (the judge's green sash is a colour, not an emblem; nothing resembles a national or court coat of arms; no text or image elements). All colours come from `avatarPalette.js`; the art and studio components contain no hex (tested). `sanitizeAvatar` makes any stored value drawable, and a test keeps the client and server vocabularies identical. The studio previews on a light and a dark surface at once, has category tabs, randomize and a 30-step undo.
31. **Phase 7 critic fixes.** Viewer is enforced in the older squad features too (workspaces, notes, cards, session sources, synthesis, hub fork) and only owner/admin moderate; the invite code is shown to admins only and rotates when a member is demoted to viewer, removed, or a viewer leaves (otherwise the code let them rejoin as an editor). Squad documents, revisions and requests keep plain author ids (no cascade from `users`, like `LawMasterNote`), so deleting one member's account never deletes or corrupts shared work; the `20261106090000_rc3_p7_squads` migration was regenerated for this before it was ever applied. History lists the accepted chain only; rebase refuses the untouched old proposal (`incorporate_head`) and the page pre-fills the current text plus the author's non-conflicting changes; direct edits are rate limited and capped at 300 revisions; announcements are never auto-hidden by reports; authors cannot delete a reported or hidden post; campus paging uses a `(createdAt, id)` cursor.
32. **Copy.** The landing hero states the new positioning (h1 = the platform sentence, lede = the three-part line) and replaces the counters with three true facts (sources on every legal text, spaced repetition, offline). Beyond the six phrases the prompt names, other unverifiable claims were removed for the same reason: "آلاف الطلبة", "مئات النوازل", the "+12" squad avatar, the code list in the toolbox card (no code is claimed to be ingested), and every "free" promise (no pricing decision exists). The brand tagline stays "المنصة الشاملة لطالب الحقوق بالمغرب": it is mirrored by `index.html`, `manifest.json` and the server brand module and pinned by parity tests, and it makes no numeric claim. Obsolete translation keys carrying removed claims were deleted from fr/en/ary. Darija stays a partial overlay (the Arabic source is its fallback, by design); fr and en are complete, enforced by a test that runs `scripts/i18n-missing.mjs`.
33. **Polish.** Both EmptyState components and the hub-level "nothing here" paragraphs now use `MascotSlot`. The responsive/bidi pass is enforced as guards (no fixed width above 360px or unprefixed 4+ column grid in the hub pages, no phone-hostile global CSS widths, mixed Latin/Arabic text isolated with `<bdi>` in ar and fr); a real-browser sweep at 360/768/1280/1920 needs the e2e environment (the a11y gate is SKIPped without a server) and is listed in the release report as not run here.
34. **Phase 8/9 critic fixes.** The server now restricts `skinTone`, `hair` and `bg` to the same closed lists as the studio (only the legacy `base` id stays free-form), and the test compares the two vocabularies in both directions and runs 200 random studio configs through the server validator. A failed avatar save keeps the studio open and says why. Empty days on the desktop week grid use a compact mascot slot (a full slot cannot fit a ~100px column); the EmptyState titles are headings again (`as="h2|h3"`). Landing copy: "texts with their sources" is now true (the Library renders the https source link recorded at ingestion) and the remaining overclaims ("كل ما يحتاجه…", "تزامن كامل", the live-support dot) were reworded. The removed-claims guard now covers Darija/English/French free-of-charge wording, inflated counts, `index.html`, the manifest and the server brand module.
